## S02.08 쉼터 엔터티·예약·저장

### SH-DATA-01 소유권

시설별 facilityId, type, level, transform, geometryVersion, capacityUnits, entrance/exit, interiorMask, restSlots, routeRevision을 관리한다. 개체별 facilityId·slotId·phase·requestedUnits·reservedUnits와 대기 시작 tick을 연결한다. 현재 상태는 목표 action과 분리한다.

### SH-DATA-02 단위와 원장

외부 표시는 공간0.5/0.75/1/1.25/1.5/2를 허용하되 내부 점유는0.25공간=1정수 단위로 계산한다. capacityUnits=occupiedUnits+reservedUnits+freeUnits, 각 값은0 이상이다. 마릿수와 구역 물 cap은 이 합계에 넣지 않는다.

### SH-DATA-03 단일 소유

한 개체는 한 시설/한 자리만 예약한다. 이동·입실중은 reserved, 실제 입실 확정 시 occupied로 원자 전환하며 이중 차감하지 않는다. 퇴실은 몸이 내부를 벗어날 때 occupied를 해제한다. 예약 토큰과 시설 버전으로 오래된 확정을 거절한다.

### SH-DATA-04 이전

0.6.3의 단일 기본 쉼터를 고정ID 기본시설/레벨1/2공간으로 이전한다. 위치·캐릭터 크기·XP·별명·물/영양·부담·손상은 보존한다. 기존 action=rest를 실입실로 복원하지 않고 형상·용량·겹침을 검증한다. 과밀한 기존 개체는 외부 대기/퇴실로 안전 재탐색하며 복제·삭제·워프하지 않는다.

### SH-DATA-05 복구·거래

영구 시설 레벨·위치·해금과 진행을 저장하고 임시 예약은 재접속 시 재검증한다. 물리적으로 내부인 개체를 안정된 ID 순으로 적합 자리와 대응시킨 뒤 남은 대기 순서를 복원한다. 저장 실패 시 시설·자리·해금·자원 변경 전체를 롤백한다. 카메라·렌더·관리자 시험은 실저장과 예약에 영향을 주지 않는다.
## S03.12 실제 쉼터 입실과 보호

## S03.14 쉼터 확장과 추가 배치

### SH-BUILD-01 확장 흐름

쉼터 선택 → 사용/예약/남은 공간 확인 → 확장 미리보기 → 배치·입구·동선 검증 → 확정 저장. 시설은2→4→6공간으로 늘며 실제 외형·내부 바닥·입구/휴식 자리도 증가한다. 숫자만 키우거나 기존 점유 캐릭터를 밀어내는 변경은 불가하다.

### SH-BUILD-02 필요에 따른 해금

첫 기본시설은 무료 제공한다. 현재 활성 비목부작 개체의 필요 공간 합계가 전체 시설 용량을 초과하거나 형상/연속 공간 때문에 입실 실패하면 다음 확장 또는 추가시설을 영구 해금하고1회 안내한다. 초기 버전은 재화·결제·반복 파밍 없이 사용자가 확정한다. 기존 장식 해금과 XP 보상을 새로 붙이지 않는다.

### SH-BUILD-03 추가시설

기본 포함 최대3동을 초기 배치 한도로 한다. 기본시설은 삭제·이동 불가, 추가시설은 이동·보관 가능하다. 추가시설은2공간부터 시작하고 최대6으로 확장한다. 확장할 자리보다 추가 배치가 안전하면 이를 제안한다. 맵 크기·기후대·편성5 상한은 바꾸지 않는다.

### SH-BUILD-04 배치 안전

영구 기본시설 외곽과 예약·사용 자리가 겹치지 않는 추가 면적, 열린 입구·출구, 물/배수·샘터 경로, 다른 지형/시설의 접근을 함께 검사한다. 실제 공간이 없으면 확정하지 않고 충돌 지점을 표시한다. 현재 개체의 퇴실이 필요한 변경은 모두 나온 뒤 다시 검증한다. 구조물을 통과시키거나 강제로 축소/워프하지 않는다.

### SH-BUILD-05 자원과 복구

시설 증가로 CARE 공유 U·샘터 물 공급이 늘지 않는다. 시설 지붕이 가리는 실제 면적만 기존 강수 예산에서 가장자리로 전환하며 새 비·저수 원천을 복제하지 않는다. 이동/보관은 사용·예약0일 때 확정, 대기자는 재탐색한다. 미리보기 취소/저장 실패는 기존 위치·수량·해금·점유를 보존한다.

## S05.16 쉼터 선택·예약·입퇴실

### SH-ACT-01 상태 전이

seeking → reserved/moving → entering → restingInside → exiting → outside. 자리가 없으면 waitingOutside, 경로가 막히면 rerouting이다. action=rest는 욕구/목표이며 확정 상태가 아니다. 내부 자리와 열린 출입 경로를 찾고 공간을 예약한 뒤 이동한다.

### SH-ACT-02 경쟁과 우선순위

같은1초 요청은 긴급 회복(강풍 위험·부담60 이상·B20 미만) → 일반 회복(기존 과습/손상/체력 조건) → 교감/보통 휴식 순이다. 같은 등급은 먼저 기다린 tick, 경로 거리, 안정된 개체 ID 순으로 선택한다. 한 스냅샷에서 공간과 형상을 원자 예약해 초과 입실을 막는다.

### SH-ACT-03 실제 도착

입구 접근점에서 멈추지 않고 진입 경로를 지나 내부 자리에 정착한다. 사용량은 입실 확정 때 증가하고 예약량은 같은 거래에서 감소한다. 몸이나 잎이 아직 밖이면 entering을 유지하며 회복·수면을 미리 시작하지 않는다. 이미 직접 놓기로 완전히 내부인 경우도 동일 검증과 예약 확정 후 입실한다.

### SH-ACT-04 예약 수명

예상 이동시간+5초를 유효기간으로 하되 최초 예약 최대30초다. 이동 진척·통로를 매초 확인한다.3초 정체면 재탐색1회, 실패/기한 초과는 해제 후 다음 후보를 찾는다. 유효 대피가30초보다 길면 가까운 경유 안전점을 먼저 선택한다. 종료·집기·편성변경으로 유령 예약을 남기지 않는다.

### SH-ACT-05 동행과 교감

A07은 수신자의 자리 확보가 우선이며 제공자가 밖에서 배웅하면 내부 자리를 차감하지 않는다. A08은 서로 다른 두 실제 자리와 두 개체 점유 합계를 함께 예약한다. 양쪽 실제 입실 뒤20초를 세며 한쪽 이탈 시 개인 휴식으로 전환한다. A13은 각자 적합 시설로 대피하고 함께 들어가려고 위험 속에서 기다리지 않는다.

### SH-ACT-06 퇴실

회복 완료/활동 재개 시 열린 출구로 나온 뒤 사용 공간을 반환한다. 입퇴실 통로는 동시 충돌을 막고 나오는 개체가 우선이다. 원래 자리에서 외부까지 이어지는 경로가 없으면 퇴실 완료·용량 반환으로 처리하지 않는다. 렌더 보간은 점유 원장을 변경하지 않는다.
## S05.17 만석·성장·안전 회복

### SH-FULL-01 다른 쉼터와 외부 대기

만석/형상 부적합이면 실제 들어갈 다른 시설과 안전 경로를 먼저 탐색한다. 없으면 입구·출구를 막지 않는 외부 대기점을 배정한다. 외부점은 현재 젖음·바람·실제 지형 보호를 검사하고 “밖에서 자리를 기다려요”로 표시한다. 보이지 않는 시설 보호·CARE를 주지 않는다.

### SH-FULL-02 위험과 순환

긴급 수신자가 기다리면 일반 휴식의 새 예약을 멈추고 회복 완료자부터 자율 퇴실한다. 건강한 점유자의 개인 휴식은 다음 안전 경계에서 끝내고 실제 퇴실 후 배정한다. 회복 중인 개체를 폭풍 속으로 밀어내지 않는다. 대기·위험·빈자리는 매초 재평가하며 긴급 조건에서 교감보다 회복을 우선한다.

### SH-FULL-03 안전의 한계 표시

외부에 안전점이 없으면 가장 위험이 낮은 도달 가능한 지점을 찾으며 대피/회복 필요 상태를 유지한다. 일반 위험 계산을 숨기거나 도착·보호를 위조하지 않는다. 확장 안내와 기존 선택 목부작을 제공한다. 단독 개체는 기본 쉼터에서 회복 가능해야 하며 모든5개체의 동시 실내 회복은 보장하지 않는다. 사망·소실·유료 구조는 추가하지 않는다.

### SH-GROW-01 성장으로 공간 증가

성장 임계 도달 때 다음 성장 단계의 공간·형상을 미리 재검사한다. 여유분을 추가 예약할 수 있으면 안전한 자리에서 단계 전환과 점유 증가를 함께 확정한다. 불가하면 현 크기로 퇴실한 뒤 새 크기/점유를 적용하고 재탐색한다. XP는 보존하며 외형 전환 대기 필드를 둔다. 안에서 갑자기 커져 겹치거나 점유 상한을 넘지 않는다.

### SH-MODE-01 종료·목부작

종료 안전 휴식은 기존 최대8시간·공유 공급 CARE를 적용하며 만석 때문에 악화시키지 않는다. 위치·물리 입실 기록·시설 사용량은 가상 증가시키지 않는다. 복귀 후 실제 위치/용량을 다시 검사하고 밖이면 이동/대기 표시다. 사용자 선택 목부작은 별도 자리에서 표현하고 시설 공간은 차감하지 않으며 편성1명은 유지한다.

### SH-MODE-02 직접 이동

들기 시 기존 내부 자리는 취소 복귀용으로 예약하되 occupied와 이중 합산하지 않는다. 새 착지는 최신 공간·형상·출구 검증과 원자 교환을 거친다. 실패하면 원래 예약 자리로 돌아간다. 그마저 무효면 가까운 유효 외부 바닥을 제안하고 이동을 확정하기 전 명시한다. 기본 쉼터의 무조건 빈자리/원격 워프를 가정하지 않는다.

## S06.12 쉼터 상태 표시와 관리자

과습/손상은 이동과 완료를 구분해 “뿌리를 말리러 가고 있어요” / “쉼터 안에서 뿌리를 말리고 있어요”처럼 표시한다. 조건 플래그만으로 도착 표현을 덮어쓰지 않는다. 카드는 같은 상태 모델을 읽으며 숫자와 애니메이션을 맞추려고 별도 판정을 만들지 않는다.

필요 공간이 부족하면 “친구들이 함께 쉴 공간을 넓혀 볼까요”와 확장/추가 배치 진입을1회 안내한다. 이전/이후 용량·실제 외곽·입구·경로를 미리 보여주고 사용자가 확정한다. 같은 부족 상태에서 반복 팝업·실패 경고를 쌓지 않는다.

### 접근·정렬

출입구 앞에서 예약된 실제 내부 자리와 공간을 확인하고 진입한다. A07의 둘은 문턱에서 겹치지 않는다. 고정 rest[5] 대신 시설별 유효 restSlots를 쓴다. 착석 준비 약0.8초는 실제 입실 확정 이후 연출이며 내부 도착 전에 회복을 시작할 근거가 아니다.

### 사용·해제

작은 호흡·느린 눈깜박임, 급수/영양은 실제 공유 예산의 전달 사건에만 연결한다. 건강 목표 후 몸을 펴고 잎을 정돈해 출구로 나온다. 위험 대피의 안정 표현도 실제 내부 도착 이후에 적용한다. 퇴실과 공간 해제는 형상 경계 기준이다.

### 목부작과 접점

목부작은 명시적 선택이며 놓기/착석으로 강제하지 않는다. entryApproach, entryPath, interiorMask, exit, restSlots, care_water, drain, feet, front_arch_mask를 같은 좌표에 둔다. 문턱·앞껍질·내부 분리, 뒤 바닥/접지 그림자 → 개체 → 앞테두리 순서로 그린다.

### 필수 클립

APK0.6.4는 실제 접근/진입/정착/휴식/퇴실 상태에 기존 걷기·수면·기본 동작을 연결했다. 별도 명명 클립 shelter_check_seat/fold_sit/care_receive의 새 원화 연출 및 A07/A08 부모 협동은 후속 범위다. 실제 상태와 문구·회복 판정은 공통 모델을 사용한다.

## APK0.6.5 쉼터 앞 경계 가림 수정

쉼터 앞 바닥/입장 경계는 모든 캐릭터 아래에 그린다. 이동 예약만으로 앞테두리를 캐릭터 위에 다시 그리지 않는다. 실제 내부 발 위치와 entering/restingInside/exiting 상태가 함께 맞을 때만 물리 나무 아치 부분을 캐릭터 앞에 표시한다. 원본 이미지의 바닥·종이 영역은 전경 가림에 포함하지 않는다. 전경 그리기는 해당 캐릭터 윤곽 범위로 한정한다.

검증: 관련 자동8개 및 UI smoke 통과. 실제 Canvas에서 외부 횡단52프레임은 앞테두리 그리기 전후 픽셀 동일. 실제 입실/확장 장면을 다시 렌더해 확인했다. 실기기 설치·성능은 미검수다. 공간 수용·생리 규칙 변경 없음.

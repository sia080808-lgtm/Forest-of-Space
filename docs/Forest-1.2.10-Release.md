# APK1.2.10 · 꽉 찬 쉼터로 헛걸음하던 문제

2026-11-22. 사용자 제보(1.2.9, 가을 깊은 밤·안개, 엘리시가 쉼터 입구에서 "쉼터 안으로 들어가고 있어요"): "쉼터 찾으러 가다가 쉼터 차 있으면 쉼터에서 나오다가 다시 쉴 곳 찾다가 차 있던 쉼터 갔다가 … 무한 뺑뺑이" → 제안(꽉 찬 쉼터는 처음부터 고르지 않기, 강풍처럼 위험할 때만 예외) → "ㅇㅇ".

- **원인(`objects.js` 쉼터 후보):** 할 일을 고를 때 쉼터는 '자리가 남았나'를 이미 앉은 친구와 자리를 잡은 친구로만 셌다. 쉼터로 걸어가는 중이지만 아직 자리를 잡지 않은 친구는 세지 않아서, 3자리가 곧 찰 쉼터를 여러 친구가 함께 골랐다. 늦게 도착한 친구는 입구에서 기다리다(8초) 다른 곳을 고르고, 잠시 뒤 다시 쉼터를 골라 같은 일을 되풀이했다.
- **수정:** 쉼터 후보를 셀 때, 쉼터로 가는 중인 다른 친구가 쓸 자리(인원·공간)까지 빼고 남는지 본다. 남지 않으면 그 쉼터를 고르지 않고 바로 이끼·바위틈·잎 그늘·햇살 바위로 간다. 강풍(바람 60 이상)처럼 위험할 때는 예전처럼 쉼터로 가서 기다린다.
- 저장 스키마·규칙 식별자 불변. 버전 1.2.10 / versionCode 96.

측정(엔진, 친구 7명, 시드 3개 × 900초): 꽉 찬 쉼터 입구에서 기다린 횟수 — 한낮 비 8 → 0, 해 질 녘 7 → 1. 쉼터 이용 시간은 같거나 늘었다.

검증: `shelter-sleep` 1.2.10 검사(친구 7명 비 오는 한낮, 꽉 찬 쉼터 입구 기다림 1번 이하 — 고치기 전 코드는 실패), 쉼터·쉼 자리·호수·스킬·관리자·날씨·산책 관련 157개 통과. `shelter-three` SH24-04·`shelter` SH-AC05는 넷째 친구가 '입구에서 기다리거나 아예 다른 곳을 고름'으로 바꿈(가짜 보호 없음·3명 상한 확인은 그대로). 전체는 CI. Android 실기기 미검증.

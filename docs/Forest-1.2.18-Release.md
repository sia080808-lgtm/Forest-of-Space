# APK1.2.18 · 봄·가을·겨울에도 호숫가로 산책, 가끔 호수 먼 물가까지

2026-11-23. 사용자 질문 "왜 친구들이 호수가로 산책을 안 가냐" → 측정(물가까지 간 산책 봄 15%·가을 10%, 여름만 44%) → "합리적인 비율 추천" → 추천 → "왜 동쪽 끝까지 안가?" → "ㄱㄱ".

- **원인(`objects.js` `strollTarget`):** 물가로 가는 산책은 여름 낮(더위 식히기, 산책의 50%)에만 있었다. 다른 산책은 1.0.1부터 지금 자리에서 0.9 안에서만 목적지를 골라서, 정원 가운데의 친구는 물가 바로 앞에서 끝났다. 봄·가을에는 동쪽 숲 가장자리를 지나던 친구만 우연히 물가에 닿았다.
- **수정:** 호수가 열려 있고 얼지 않은 낮에는 산책 중 일부가 가장 가까운 빈 물가로 간다: 봄 30%, 여름 50%(그대로, 더위 식히기), 가을 25%, 얼지 않은 겨울 15%. 언 겨울은 예전처럼 얼음 위 산책(30%). 카드는 "호수 물가로 산책 가고 있어요" / "물가에서 호수를 구경하고 있어요".
- **먼 물가(사용자 "왜 동쪽 끝까지 안가?"):** 아침(하루 1,200초 중 처음 400초, 해 질 녘보다 한참 전) 물가 산책의 4분의 1은 호수 둘레 아무 물가(지금 자리에서 0.6 넘게, 동쪽 끝 포함)로 간다. 갈 시간이 넉넉하도록 이때만 산책 기한을 2.5배(225초)로 둔다. 1.0.1에서 산책을 0.9 안으로 막은 건 멀리 간 친구가 할 일을 고를 때마다 먼 길을 새로 찾아 느려졌기 때문인데, 1.1.4부터 찾은 길을 다시 써서 가끔 멀리 가는 정도는 가볍다(아래 측정).
- 호수가 닫혀 있으면 예전과 똑같이 고른다(난수도 그대로 씀).
- 저장 스키마·규칙 식별자 불변(산책 기록에 `view` 추가, 없으면 그대로). 버전 1.2.18 / versionCode 104.

측정(엔진, 친구 6명, 호수 열림, 시드 2개 × 2,400초, 고치기 전 → 고친 뒤): 물가까지 간 산책 봄 34/297(11%) → 65/288(23%), 여름 67/257(26%) → 61/251(24%), 가을 27/239(11%) → 38/240(16%). 먼 물가(x 2.0 넘게)로 간 산책 1~3 → 5~8번(도착 3~4). 엔진 시간: 봄·가을 평균 4.1~4.5ms로 거의 같음. 여름 한 시드(4)에서 50ms 넘는 순간이 29 → 282번으로 늘었는데, 먼 물가와는 상관없이 비 오는 날 엘레판 잎 우산 아래 두 친구가 매초 갈 곳을 다시 찾는 기존 상황에 이번엔 걸린 것이다(난수 순서가 바뀜). 다른 여름 시드 6개는 고치기 전과 같거나 적었다(고치기 전 18~42 → 14~34). 이 우산 아래 반복은 따로 고칠 일.

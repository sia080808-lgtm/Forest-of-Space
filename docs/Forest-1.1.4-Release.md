# APK1.1.4 · 렉 줄이기: 길찾기 다시 쓰기, 화면 조명 가볍게

2026-11-21. 사용자 요청: "용량이 많아지면서 렉이 조금씩 걸리는데 안걸리게 하는 법 없니" → 측정(엔진 시간의 약 75%가 길찾기, 화면 그리기의 약 65%가 화면 전체 조명 단계) → "1,2번 ㄱㄱ".

변경 내용(규칙 수치·화면 모습 그대로):
- **걷는 길 다시 쓰기(`spatial.js` `planFor`·`keptPlan`):** 걷는 친구가 매초 길을 처음부터 다시 찾던 것을, 찾은 길을 친구 기록(`walkPlan`)에 두고 다시 쓴다. 목적지가 같고 다음 구간이 비어 있으면 그대로 걷고, 막히거나 목적지가 바뀌거나 길이 끝나거나 8초가 지나면 다시 찾는다. 목적지까지 곧장 갈 수 있으면 그쪽이 먼저다. 길을 못 찾았을 때(가장 오래 걸리는 경우)는 3초 동안 다시 찾지 않는다(같은 자리일 때). 저장에 함께 남아 다시 불러와도 같은 길로 걷는다.
- **"갈 수 있나" 확인 다시 쓰기(`spatial.js` `route`):** 할 일 고르기·쉼터 줄 서기에서 같은 두 점을 다시 물으면, 배치·친구 크기·쉼터가 같을 때 앞의 답을 쓴다(답은 같고 계산만 줄어듦).
- **화면 조명(`scene.js` `draw`, `world-effects.js` `gradeOver`):** 세계를 따로 한 장에 그린 뒤 밝기·채도 필터를 씌워 화면에 다시 옮기던 것을, 화면에 바로 그리고 가벼운 겹치기(곱하기·채도 섞기)로 같은 빛을 낸다. 바꾸기 전후 그림 차이는 색값 최대 2/255.
- 저장 스키마·규칙 식별자 불변(친구 기록에 `walkPlan` 추가, 없으면 그대로 불러옴). 버전 1.1.4 / versionCode 80.

측정(같은 장면: 친구 6명, 여름 호수 채움, 컴퓨터 Node — 휴대폰 숫자는 다를 수 있음):
- 엔진 한 번(1초): 평균 13.0ms → 5.5ms, 50ms 넘게 걸린 순간 2,400번 중 107 → 22, 16ms 넘은 순간 448 → 100.
- 화면 한 장: 약 20ms → 7.5ms(기본 화면·전체 보기, 낮·밤 같음).

검증: 관련 테스트(바위·쉼 자리·쉼터·산책·호수·넓은 숲·렌더·스킬) 통과, 전체는 CI. Android 실기기 미검증.

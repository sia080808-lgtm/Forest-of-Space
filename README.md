# APK1.1.9 · 영상이 몇 초로만 보이던 문제

2026-11-21. 사용자 제보(1.1.8 실기기): "꽤 오래 녹음했는데 정작 3초 녹화되는데".

- **원인:** 웹 화면의 녹화기(MediaRecorder)는 조각으로 이어 붙이는 MP4(fragmented MP4)를 만든다. 크롬에서 같은 방식으로 약 20초를 찍어 보니 영상 내용은 끝까지 들어 있었지만(약 480장, 조각 5개), 파일 머리말의 전체 길이는 0초, 트랙 길이는 영상 0.2초·소리 0.13초로 적혀 있었다. 갤러리 앱은 이 머리말을 읽어 길이를 보이고 재생을 멈추기 때문에 몇 초로만 보였던 것으로 판단한다(실기기 파일은 확인하지 못함).
- **수정(`MainActivity.java` `videoEnd`·`remux`):** 녹화 조각을 먼저 앱 임시 파일에 모은 뒤, 멈출 때 Android의 MediaExtractor·MediaMuxer로 영상·소리를 한 장씩 옮겨 담아 보통 MP4(WebM은 WebM)로 다시 만들어 갤러리 `동영상/여백의 숲`에 저장한다. 이때 실제 길이가 머리말에 적힌다. 이 변환이 실패하는 기기에서는 녹화된 그대로 저장한다(1.1.8과 같음). 임시 파일은 저장 뒤 지운다.
- **화면(`forest-app.js`):** 멈춘 뒤 변환하는 동안 "영상을 저장하고 있어요…"를 띄운다.
- 저장 스키마·규칙 식별자 불변. 버전 1.1.9 / versionCode 85.

검증: `MainActivity.java` javac(Android 15 API) 컴파일, `android-shell-dex`(람다 없음)·`package` 통과, 크롬에서 녹화 → 멈춤 흐름 확인. 크롬 녹화 파일 분석으로 머리말 길이 0초 확인. **MediaMuxer 변환은 Android에서만 돌아서 이 환경에서 실행해 보지 못했다** — Android 실기기에서 길이가 제대로 나오는지 확인 필요.

# APK1.1.8 · 영상이 저장되지 않던 문제 고침

2026-11-21. 사용자 제보(1.1.7 실기기): "왜 영상을 저장하지 못한다고 뜰까? 맵 움직이면 안댐?"

- **원인(`forest-app.js` `toBase64`):** 녹화 조각을 Android로 넘길 때 데이터 URL을 첫 쉼표에서 잘라 내용만 꺼냈다. 그런데 영상 형식 이름 자체에 쉼표가 들어 있어서("video/mp4;codecs=avc1,mp4a.40.2") 내용 대신 형식 이름 조각을 넘겼다. Android가 첫 조각을 읽지 못해 녹화 전체가 실패로 끝나고 "영상을 저장하지 못했어요"가 떴다. 맵을 움직인 것과는 상관없다. 1.1.7 크롬 확인은 브라우저 내려받기 경로라서 이 문제가 드러나지 않았다.
- **수정:** ";base64," 뒤를 내용으로 쓴다. 맵 끌기·전체 보기 전환을 하며 찍어도 조각이 끝까지 넘어간다(크롬 + Android 다리 흉내, 약 1.1MB).
- 저장 스키마·규칙 식별자 불변. 버전 1.1.8 / versionCode 84.

검증: 크롬에서 Android 저장 다리를 흉내 내어 녹화 → 맵 끌기·전체 보기 → 멈춤, 조각 2개·약 1.1MB가 실패 없이 넘어감(고치기 전 같은 시험은 조각 0개·실패). `package` 통과. 전체는 CI. Android 실기기 미검증.

# APK1.1.7 · 월드 영상 녹화 (최대 1분)

2026-11-21. 사용자 요청: "일정시간 월드를 비디오 녹화하는 기능 넣을 수 있나" → "그냥 최대 시간은 1분으로 지정해두고, 그 안에서 찍다가 정지하는 게 좋을 거 같음".

변경 내용(화면·Android 셸, 게임 규칙·저장 불변):
- **녹화 버튼(`index.html`·`forest-app.js`·`forest.css`):** 오른쪽 위 사진 버튼 아래에 캠코더 아이콘(사진 아이콘과 같은 모양, 사용자 요청). 누르면 녹화를 시작하고, 버튼이 빨간 정지 표시와 남은 시간(1:00부터 줄어듦)으로 바뀐다. 다시 누르면 멈추고 저장한다. 1분이 되면 저절로 멈춘다. 앱이 뒤로 가면(화면 꺼짐 등) 그때까지 찍은 것을 저장한다.
- **찍히는 것:** 사진처럼 월드 그림판만(버튼·안내·카드 없음, 친구 선택 링은 녹화 동안 숨김). 끌어 보기·확대·축소한 그대로 담긴다. 초당 30장, 약 2.5Mbps(1분 약 19MB). 게임 소리(배경음·효과음)도 함께 녹음한다(소리 크기 설정 그대로, `audio.js` `stream`).
- **형식:** 기기가 지원하면 MP4, 아니면 WebM. 크롬 확인: MP4(H.264 영상 + Opus 소리).
- **저장(`MainActivity.java` `videoBegin`·`videoChunk`·`videoEnd`):** Android는 갤러리 `동영상/여백의 숲`에 1초마다 조금씩 바로 써서 1분 영상도 메모리에 한꺼번에 들고 있지 않는다. Android 10 이상 MediaStore라 권한이 필요 없다. 실패하면 만들던 파일을 지운다. 브라우저에서는 파일로 내려받는다.
- 저장 스키마·규칙 식별자 불변. 버전 1.1.7 / versionCode 83.

검증: `package`·`android-shell-dex` 통과, UI PASS, `MainActivity.java` javac(Android 15 API) 컴파일 확인. 실제 크롬(Playwright)에서 3초 녹화 → 멈춤 → MP4 내려받기, 영상·소리 트랙 확인(786×1308). 화면 `docs/qa-1.1.7/runtime/recording.png`·`buttons.png`. 전체는 CI. **Android 실기기 미검증**(WebView의 MP4 지원 여부, 갤러리 저장, 녹화 중 렉).

# APK1.1.6 · 렉 줄이기 2: 화면 한 장 그리는 비용

2026-11-21. 사용자 요청: "원래 이런 게임 돌리면 폰 자체가 좀 렉이 걸리나" → "일반 모바일 게임처럼 그래픽 칩에서 하면 되나" → 한 장 그리는 비용 줄이기 → "한장 그리는 비용줄이기 하면 퀄 낮아보일까" → "ㄱㄱ".

측정 방법: 실제 크롬 브라우저(그래픽 칩 없는 소프트웨어 그리기, 휴대폰 크기 393×690 · 화면 배율 2.5)에서 친구 6명·여름 호수 채움 장면을 그린다(`tools/render-bench.cjs`). 컴퓨터 Node 그림판은 필터·임시 그림판 비용이 브라우저와 크게 달라서(1.1.4까지의 측정 방식) 이번에는 브라우저로 쟀다.

찾은 원인과 변경 내용(그림·규칙 그대로, 렌더 전용):
- **떨어진 낙엽(`scene.js` `drawFallenLeaf`·`bakeLeaf`):** 낙엽 한 장마다 그림자를 흐림 필터(`blur`)로 매 장 다시 그렸다(한 장의 절반 이상). 낙엽 모양마다 그림자·종이 질감·겨울 흰빛·가을 물듦을 한 번 구워 두고 같은 변환으로 그린다. 낙엽 자리의 잎과 거름 조각도 같은 방식.
- **사물의 젖은 모습(`terrain`·`creviceFront`·`wetTile`):** 바위·바위틈·이끼·낙엽 자리는 흙이 촉촉하면(거의 늘) 밝기·채도 필터를 매 장 씌웠다. 젖은 정도(1/20 단위)마다 화면에 그려지는 크기로 필터를 입힌 그림을 미리 만들어 둔다. 마른 사물은 필터 없이 그린다.

- 수정: `MainActivity.java`의 람다·메서드 참조 10곳을 같은 동작의 익명 클래스(Runnable·ValueCallback·OnApplyWindowInsetsListener·FilenameFilter·Comparator)로 교체. 웹 게임·에셋·저장 형식·저장 경로 불변. 시작 단계에서 종료되어 저장 데이터는 손상되지 않았을 것으로 판단.
- 재발 방지: `tests/forest/android-shell-dex.test.cjs`(셸 소스에 람다/메서드 참조 금지), `tools/build_apk_alt.sh`(대체 빌드 도구 사용 시 dex에 `LambdaMetafactory`가 있으면 빌드 실패).
- 버전 0.6.13 / versionCode 30. 0.6.12(29)를 설치한 기기와 0.6.11(28) 기기 모두 위에 업데이트 가능(같은 키 서명 시).
